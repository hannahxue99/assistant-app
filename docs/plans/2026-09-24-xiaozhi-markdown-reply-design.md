# 小知最终回复 Markdown 渲染设计

## 背景

模型会自然使用 Markdown 组织长回答。当前小知把最终回复放进单个 React Native `Text`，导致 `**加粗**`、`- 列表` 等标记直接暴露，段落层级和长列表换行也不清晰。

## 产品决策

只对小知最终回复正文启用受控 Markdown。用户消息、思考过程、处理阶段、来源入口和操作回执继续使用现有组件，避免模型格式影响交互信息层级。

首版支持：

- 段落、换行、加粗和斜体。
- 一至三级标题，但映射为适合气泡的克制字号。
- 有序与无序列表，长行使用悬挂缩进。
- 引用、分隔线、行内代码和代码块。
- 仅 `http` / `https` 链接。

首版不支持：

- 原始 HTML。
- 远程图片。
- 表格。
- 任意协议链接。

## 视觉

```text
┌──────────────────────────┐
│ 确认无误的                 │  小标题/加粗，不显示 **
│                            │
│ • TypeSafe AI 出品……       │
│   换行后与正文起点对齐       │
│ • 发布日多数来源写……        │
│                            │
│ 上次没说全、这次补上的       │
│                            │
│ • 采用的数据更完整……        │
└──────────────────────────┘
```

正文继续使用当前小知气泡的颜色、宽度和 22px 行高。标题只提高字重和少量字号；列表段间距小于段落间距，避免长回答被拉得过散。

## 实现与数据流

1. SQLite 和消息协议继续保存模型返回的原始 Markdown，不改 schema，不迁移历史消息。
2. `AssistantMessageBubble` 仅在 assistant 正文分支调用独立 `AssistantMarkdown` 组件。
3. 组件使用成熟 Markdown parser，关闭 HTML，并覆盖图片、表格与链接规则。
4. 链接先经过本地 URL 校验，只允许无凭据的 HTTP(S) 地址，再交给系统浏览器。
5. 流式回复复用同一组件，光标作为正文后的独立文本节点显示；半截 Markdown 必须安全降级，不得导致页面崩溃。

## 边界情况

- 未闭合的 `**`、反引号或代码围栏。
- 中文、英文和 URL 混排换行。
- 嵌套列表、空列表项和超长单词。
- 恶意 HTML、`file:`、`javascript:`、带用户名密码的 URL。
- 旧消息是纯文本时保持原样显示。

## 验收标准

- `**文字**` 显示为加粗，不暴露星号。
- `-` / `1.` 列表使用真实项目符号或序号，长行换行对齐。
- 段落、标题、引用和代码层级清楚且不突破气泡宽度。
- 仅安全 HTTP(S) 链接可打开；HTML、图片、表格和危险协议不执行。
- 用户消息、思考过程、处理状态、来源和回执样式无变化。
- 已存历史消息无需迁移即可获得新渲染。
