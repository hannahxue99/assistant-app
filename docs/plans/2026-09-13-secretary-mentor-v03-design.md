# “秘书 + 导师”V1 产品与技术设计（原 V0.3）

状态：完整愿景已正式升级命名为 V1；本文保留原文件名用于历史链接，当前总纲与实现进度以 [`PRD.md`](../../PRD.md) 为准
产品一句话：一个长期懂你的私人 AI：像秘书一样帮你料理当下，像导师一样帮你看清方向。

## 1. 目标与边界

V1 的目标不是增加一个聊天机器人，而是打通一个可以持续运转的个人协助闭环：用户只需要自然地对“小知”说话；系统保存完整表达，理解并形成待办、事件或长期记忆；首页负责呈现本周行动与有增量价值的教练提醒；后续对话继续推动事情发展。

首版必须同时具备：三个 Tab、连续且可回看的对话、待办 / 事件 / 长期记忆四类独立数据、可重建的当前状态快照、每日复盘、首页提醒、提醒回到对话继续处理、统一搜索及旧数据迁移。

首版明确不做：云端调度、主动推送、外部系统代办、用户可见的长期待办页、手动会话管理、秘书 / 导师模式切换、复杂知识图谱、自动事件归档。

## 2. 信息架构与页面

### 首页

首页只回答“现在值得关注什么”，不承担输入和资料库功能。

1. 本周待办：保持现有能力，只展示有日期且落在本周的未完成待办。
2. 教练提醒：最多 5 条，不重复待办，只展示遗漏、冲突、停滞、机会、关联或反复模式。每条说明原因，支持点击处理与“不再提醒”。
3. 事件列表：由现有聚合主题升级而来，展示全部事件；置顶优先，其余按最近更新时间排序。卡片展示事件名和当前状态。

不再展示长期待办、用户原声 Tab、搜索框或底部输入框。

### 小知

小知是唯一输入入口，也是完整消息历史的唯一用户界面。用户看到一条连续对话流，不需要创建、切换或命名会话；后台按语义自动分段。普通进入保持安静，不自动问候、不弹键盘、不调用模型。只有从提醒或事件携带上下文进入时，小知才发送一条可保存的推进消息。

每轮输出保持同一种消息形态。若本轮改变了数据，在回复下方合并显示“已处理”回执，例如“建立待办、更新事件、记住偏好”，并只提供必要的撤销或更改入口。

右上角提供统一搜索，覆盖对话、事件、待办和已生效长期记忆。

### 我的

“我的”首先展示已生效的长期记忆，设置与数据管理位于下方。记忆采用原子卡片，一张卡只表达一项跨事件仍成立、会影响未来协助方式的认知；用户侧仅显示类别、简短内容、“修改 / 忘记”，不显示依据、来源、置信度，也不设置手动新增按钮。

原画像卡移除。稳定偏好、原则、长期目标和反复模式迁移为长期记忆；有时限目标进入当前状态，持续主线可形成事件；含义不清或过期值保留原始来源，之后在合适对话中确认。

## 3. 关键交互

### 普通对话

1. 用户消息先本地保存，确保失败时原话不丢。
2. 系统组装最近对话、当前段摘要、相关历史段、事件、待办和记忆。
3. 一次模型调用返回自然回复与拟执行操作。
4. 本地校验准入、权限、歧义、日期和幂等约束。
5. 在一个事务中保存助手消息、有效对象、关系与回执。
6. 若行动意图没有日期，待办先隐藏保存，小知在当前对话最多追问一次时间；未回答不阻塞对话。

### 提醒处理

提醒生成时同时生成一条“背景 + 一个推进问题”的预备接话。用户点击提醒进入小知时只落库该接话，不再调用模型。仅打开不算已处理；若用户没有回应便离开，首页重新显示该提醒并标记“继续处理”。用户给出相关回应或触发实际操作后，原提醒退出。以后只有出现新信息、新机会或新判断时，才能生成新的提醒。

“不再提醒”只抑制这一条提醒及其等价重复，不删除事件、待办或消息，也不禁止未来因实质变化产生不同提醒。

### 事件详情

事件详情依次展示事件名、更新时间、置顶 / 更多、当前状态、已经安排时间的关联待办、关键进展。进展只追加有意义的变化，当前状态可以更新。页面不设输入框；“和小知聊这件事”回到同一连续对话并携带事件上下文。

### 统一搜索

精确搜索完全本地执行，不调用模型。默认“全部”按关系归组：确有关联的事件、待办和对话合成一个事件组，子项可以直达具体对象；长期记忆独立展示；无关系的同词命中不强行合并。顶部提供“全部 / 事件 / 对话 / 待办 / 记忆”筛选。隐藏待办允许被主动搜索找到，但不形成可浏览的全部待办页。

## 4. 数据模型

V1 保留 SQLite 本地优先架构，把现有 `entries` 渐进迁移为下列一等对象：

- `messages`：用户与助手的完整原文、角色、时间、请求编号、状态和所属后台分段。
- `conversation_segments`：消息范围、可重建摘要、更新时间和估算容量；不在 UI 展示。
- `events`：标题、当前状态、置顶状态和更新时间。
- `event_updates`：事件关键进展，只追加，可关联来源消息或待办变化。
- `todos`：行动内容、日期、完成状态和可见性；无日期行动使用 `hidden`。
- `memories`：类别、原子内容、准入状态、敏感等级、生效 / 替代时间。
- `object_relations`：消息、事件、待办和记忆之间的来源、关联、延续或派生关系。
- `coach_reminders`：提醒内容、原因、预备接话、生命周期状态和去重键。
- `current_state_snapshot`：可重建的后台缓存，包含版本、生成时间和结构化当前状态。
- `daily_review_runs`：每日复盘的日期、输入版本、结果与失败状态，确保幂等。
- `search_documents` + FTS：四类用户可检索对象的统一本地搜索投影。

长期记忆状态至少区分 `candidate / active / superseded / forgotten`。只有 `active` 出现在“我的”和普通检索结果。所有来源保留在后台；删除单个来源后重新计算认知是否仍有有效证据，不机械级联。

## 5. 运行架构与数据流

采用“本地事务核心 + 单次结构化模型调用 + 可重建派生层”，不引入服务端或消息队列。

主对话数据流：

`用户输入 → messages 先保存 → 上下文选择 → 一次模型调用 → 本地操作校验 → SQLite 事务保存 → UI 显示回复和回执`

每日复盘数据流：

`后台任务或进入 App → 检查当天运行记录与输入版本 → 无变化则本地跳过 → 有变化时组装当前状态 → 一次模型调用 → 本地证据 / 增量价值 / 去重校验 → 保存最多 5 条首页提醒`

Expo 57 的后台任务由系统择机执行，并不保证准点；用户杀死 App 后任务可能停止。因此后台任务只负责“尽力提前生成”，任意页面进入时的幂等补跑才是正确性保障。后台任务需要新增原生依赖和配置，实施后必须重建并安装 App，不能只依赖 Metro Reload。

## 6. Token 与调用成本控制

1. 每条用户输入最多一次主模型调用；回复、对象操作建议和必要的分段摘要增量共用该结果。
2. 精确搜索、筛选、对象排序、待办投影、状态机和事务校验全部本地完成。
3. 上下文默认保留最近 6 轮原话、当前段摘要、最多 3 个相关历史段，以及每类最多 5 个相关结构化对象；超限时按相关性和新鲜度裁剪，而不是无限拼接历史。
4. 只有明显语义切换或容量超过软上限才结束分段；摘要在分段结束或出现重大状态变化时更新，不逐消息单独调用模型。
5. 每日复盘先比较结构化输入版本；没有新消息、事件、待办或记忆变化时不调用模型。
6. 当前状态快照增量更新；失败时使用旧快照并临时补入最新结构化变化，之后重建。

具体 Token 上限作为配置项，在选定模型的设备测试中校准，不成为用户可见设置。

## 7. 失败、冲突与隐私边界

- 模型或网络失败：保留用户消息，显示可重试状态，不创建对象，不伪造已处理回执。
- 事务失败：助手回复和拟操作均不标记成功；同一请求编号重试不会重复创建对象。
- 事件归属不确定：低风险时保存独立消息，暂不强行建事件；后续证据充足再回溯关联。
- 长期记忆冲突：新认知不能静默覆盖旧认知；明确纠正时替代，推断冲突时在合适对话中确认。
- 敏感记忆：默认不保存，或必须明确确认后生效。
- 删除来源消息：先说明受影响对象，允许只删消息或同时删衍生内容；仍有其他有效来源时保留对象。
- 后台复盘受系统中断：保存幂等运行状态，下次进入 App 补跑；不向用户承诺固定时间完成。
- 搜索关系缺失：分别展示结果，不凭关键词聚合。
- 提醒误点：仅打开不消耗提醒；没有回应返回首页时显示“继续处理”。

## 8. 迁移策略

迁移只新增结构并复制 / 投影旧数据，不直接删除旧 `entries` 或 `profile` 字段。旧数据在验收完成前继续作为回滚来源。

1. 每条旧 `entry` 生成一条用户 `message`，保留原文、时间、来源和旧 ID 映射。
2. 有日期的 task 迁移为可见待办；无日期 task 迁移为隐藏待办。
3. 旧 topic 迁移为 event；原 topic 内条目成为来源消息，结合现有摘要生成初始状态与历史。
4. profile 中稳定内容迁移为候选或已生效长期记忆，时间性目标进入当前状态；歧义内容保留待确认。
5. 建立搜索投影并校验旧记录数量、关系数量和可回查性。
6. 迁移完成后小知只显示一次合并回执。出现异常时回滚新表版本，旧数据仍可由现版本读取。

## 9. 实施拆分

用户确认本设计后，在独立 `codex/` 分支实施并通过一个可审查 PR 交付。

1. 数据层：新增版本化迁移、实体类型、仓储函数、关系和统一搜索投影；先完成迁移与回滚测试。
2. 运行层：新增上下文选择、单轮编排、本地操作校验、幂等事务、快照、会话分段和每日复盘。
3. 页面层：三 Tab 导航、小知连续对话、首页提醒 / 事件、事件详情、我的记忆、统一搜索。
4. 迁移层：旧 entry / topic / profile 迁移与一次性回执。
5. 验证层：所有新增测试注册进 `npm test`，运行 `npm run ci`；后台能力、导航和迁移在真实设备验收。

预计主要改动位置：`app/(tabs)`、新增 `app/event` 与搜索路由、`src/types.ts`、`src/db.ts`，以及新增 `src/assistant`、`src/search`、`src/coaching`、`src/migrations` 和对应测试脚本。现有日历、通知、备份和编辑能力通过适配层继续工作，不做无关重写。

## 10. 验收标准

1. 用户从小知发送普通记录、明确事务或困惑时，无需选模式；消息重启后仍完整可见。
2. 一次输入可以在同一轮形成多个对象，但只显示一个合并回执；重试不重复创建。
3. 有日期待办进入本周；无日期行动保存但不出现在首页，并最多追问一次时间。
4. 持续事项正确创建或更新事件；事件状态更新、关键进展只追加，普通寒暄不进入进展。
5. 符合准入的长期记忆出现在“我的”，推断性 / 敏感内容不未经确认生效；记忆可修改、忘记和撤销。
6. 首页最多显示 5 条提醒，且不复述待办；每条有原因，可处理或不再提醒。
7. 点击提醒只落一条预备接话；未回应返回后显示“继续处理”，回应后原提醒退出。
8. 普通进入小知不生成消息、不调用模型、不自动弹键盘。
9. 搜索能覆盖四类对象；有关联结果正确归组，无关联同词结果不误合并，类型筛选可查看完整结果。
10. 每日复盘无数据变化时不调用模型；后台未运行时，进入任意页面可幂等补跑。
11. 模型、网络、事务或迁移失败时不丢用户原话、不显示虚假成功、不破坏旧数据。
12. 旧原声、待办、主题和画像可以在新结构中回查，迁移数量校验通过。
13. `npm run ci` 通过；真实设备完成消息、提醒、后台补跑、搜索、迁移和重启恢复验收。

## 11. 关键架构决策

### ADR-01：渐进迁移，不整体重构

选择：在现有 Expo Router + SQLite 应用中新增实体与页面，保留旧表作为迁移来源。
代价：过渡期存在适配层和少量重复数据。
原因：最小化已有待办、日历、通知、导入导出和历史数据的回归风险，并提供明确回滚点。

### ADR-02：本地为事实来源，模型只提出操作

选择：模型输出自然回复和拟操作，本地负责权限、准入、日期、关系、幂等和事务。
代价：需要显式操作协议与更多本地测试。
原因：避免模型直接写数据造成重复、越权或虚假回执，同时控制调用成本。

### ADR-03：派生内容可重建

选择：分段摘要、当前状态快照、搜索投影和教练候选均视为可重建派生层。
代价：需要版本和重建逻辑。
原因：完整消息和结构化对象才是长期事实，派生缓存不应成为不可恢复的数据孤岛。
