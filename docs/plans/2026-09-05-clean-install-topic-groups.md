# 第三批：空白安装与完整主题统计

范围：沿用现有首页卡片和详情布局，不新增用户入口。

首次启动：数据库初始化 → 空首页；恢复个人历史记录通过现有导入入口。移除已完成的一次性个人迁移调用和源文件，不删除已落库的记录，历史源码仍可从 Git 恢复。

聚合查询：全库按主题计数 → 每个主题取一条最新记录 → 置顶优先，组内 updatedAt 排序 → 卡片显示完整 count → 点击后按主题读取完整详情。

不再先截取200条原声再分组。列表模型删除容易误用的部分 entries，明确使用 count/latest；未聚合列表按记录本身 topic 是否为空判定。

验收：新建空库无个人内容；单主题超过200条仍显示完整数量；旧置顶主题不丢失；超过200个主题仍存在；点击详情数量一致；原声/导出记录保持完整。

验证使用内存 SQLite，不操作用户数据库。无 schema、原生依赖或权限变更，Reload 验收。PR 基于第二批 codex/entry-consistency，第二批合并后再转向 main。知识沉淀在用户验收后完成。

边界：原声时间流现有500条限制、超大主题数量的虚拟列表优化、通知删除补偿不在本批实现。回滚第三批 PR 可恢复原行为；无需回滚数据库。
