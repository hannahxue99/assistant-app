# 首页事件卡与待办导航精简设计

状态：已实施，等待 Dev 真机验收

视觉稿：

- [事件卡与待办交互 Before / After](../../design/event-card-todo-flow-v11.svg)
- [首页待办双 Tab 与小知跳转](../../design/todo-tabs-navigation-v13.svg)

## 1. 首页事件卡

事件卡恢复为稳定的三层信息结构，卡片目标高度约 118–126px：第一行标题、第二行直接显示进展内容、第三行最新更新时间。卡片上不增加“当前进展”标签。标题与进展分别最多显示一行，超出省略；没有进展时仍保留第二行并显示“暂时还没有明确进展”，避免不同卡片高度跳动。时间固定在底部，不再与标题争抢横向空间。

右上角增加 44×44 的独立置顶按钮，视觉完全复用旧版本现有的 `TopicPinIcon`：SF Symbols / 对应平台图钉、旋转 45 度，未置顶为灰色线性图标，置顶为金色实心图标，不增加圆形底座或新图标。点击图标只切换置顶并原地刷新列表，不进入详情；点击卡片其他区域才进入事件详情。

排序规则：置顶事件始终在普通事件之前；置顶区内部、普通区内部都按事件 `updated_at` 从新到旧排序，ID 作为稳定兜底。置顶操作更新 `pinned_at` 与 revision，但不修改 `updated_at`，因此不会伪造事件新进展，也不会改变同一区域内的时间顺序。

## 2. 事件详情

详情页顶部只保留返回按钮，删除右上角置顶和“…”入口，同时删除由“…”进入的重命名编辑态。详情内容、相关待办勾选、关键进展和“和小知聊这件事”保持不变。事件置顶统一在首页完成；事件改名仍可通过小知语义操作完成，首版不提供详情页手工改名入口。

## 3. 待办不设详情页

待办没有独立详情体验。本轮不再为即将迭代掉的“用户原声”页面和历史入口设计兼容规则，只处理当前产品入口：

- 首页本周待办维持“只勾选完成”，不新增点击跳转。
- 事件详情中的相关待办，点击文字不跳转，勾选框仍可完成/取消完成。
- 小知的待办操作回执点击后回到首页；小知的事件回执点击后进入对应事件详情。

待办内容或时间需要修改时，用户通过小知表达修改；本次不新增待办编辑弹层。

### 3.1 首页“本周待办｜全部待办”双 Tab

首页待办模块标题改成 `本周待办｜全部待办`，两个 Tab 均可点击，不进入新页面。默认选中“本周待办”；“本周待办”保持 20px 主标题字号，“全部待办”使用约 15px 的较小字号。选中项使用正文色与短橙色下划线，未选中项使用 `textDim`；不使用胶囊或按钮底色。视觉字号可以不同，但两个点击区域都保持至少 44px 高，并提供正确的选中态辅助信息。

沿用现有口径，“本周待办”是今天起 7 天窗口，不是自然周。“全部待办”虽然保留用户指定的名称，但内容只显示 7 天窗口之后、已有日期且尚未完成的待办，不包含本周事项，避免两个 Tab 重复；按到期时间升序并按日期分组。逾期待办、已完成待办和无日期隐藏待办不进入。

采用用户指定的首页双 Tab，不再新增“全部待办”页面。“全部待办”较长时会把后续事件区向下推，切回“本周待办”即恢复紧凑首页。正常首次进入默认本周；当前 App 会话内保留用户最后一次手动选择，小知的定向跳转可以覆盖该选择。

### 3.2 小知待办回执精准跳转

小知待办回执根据落库后的 `dueAt` 与同一个 7 天窗口判断目标：

- 今天起 7 天内：进入首页、选中“本周待办”，定位并短暂高亮对应行。
- 7 天窗口之后：进入首页、选中“全部待办”，定位并短暂高亮对应行。
- 无日期待办：继续按既定规则隐藏，回执不提供列表跳转；小知在对话中追问时间。

跳转携带 `focusTodoId`，页面只用它定位，不改变查询范围或创建临时数据。高亮用于确认到达目标，随后恢复普通卡片样式。事件回执仍直接进入事件详情。

## 4. 状态与边界

- 置顶写入期间仅禁用当前卡片的置顶按钮，其他卡片仍可浏览；失败则恢复原状态并给轻量错误提示。
- 置顶请求遇到 revision 冲突时重新加载最新列表，不覆盖小知刚更新的事件状态。
- 事件被小知更新后，下一次首页刷新按新的 `updated_at` 自动重排。
- 无进展、超长标题、动态字体、置顶/取消置顶、快速连续点击和列表读取失败均需覆盖。
- 取消待办详情不删除待办数据、日历映射或通知，只移除当前产品入口中的详情跳转。
- “全部待办”读取失败只替换待办模块为局部错误和重试，事件区仍可使用；空态显示“本周之外没有待办”。
- 小知回执指向的待办已被完成或删除时，首页正常打开并给出轻量提示，不恢复或复制该待办。

## 5. 验收标准

1. 每张事件卡稳定显示标题、进展内容、最新时间三层，不出现“当前进展”标签，视觉高度与图稿一致。
2. 卡片置顶按钮具有 44×44 点击区域；点击时不误进详情，点击正文仍能进入事件详情。
3. 置顶优先；置顶区与普通区分别按 `updated_at DESC, id DESC` 排序，置顶动作不冒充内容更新时间。
4. 事件详情右上角没有置顶、“…”和重命名编辑态。
5. 首页和事件详情不能进入待办详情；相关待办仍可直接勾选完成。小知待办回执进入首页，小知事件回执进入事件详情。
6. 本轮不修改即将下线的用户原声页面，也不为历史待办入口增加额外兼容代码。
7. 首页显示 `本周待办｜全部待办` 两个可点击 Tab，默认本周；“全部待办”字号始终更小，选中态清晰且各有 44px 点击高度。
8. “全部待办”在首页同一区域只显示 7 天窗口之后的有日期未完成待办，不与本周重复，并按日期升序分组；切回本周恢复 7 天列表。
9. 小知创建的本周待办跳首页并选中本周，更远待办跳首页并选中全部；两者定位目标并使用同一个 7 天边界。
10. 新增排序、导航目标、Tab 状态、卡片状态和详情行为测试进入统一 `npm test`；交付前 `npm run ci` 与 GitHub `CI / validate` 通过。
11. 使用现有 Dev Tunnel Reload 真机验证，不启动第二个 Metro，不要求用户手动重装。

- `src/components/AssistantEventCard.tsx`：三行布局、右上置顶按钮和状态。
- `app/(tabs)/index.tsx`：待办双 Tab、全部待办投影、定向定位、置顶动作、错误处理和刷新。
- `src/db.ts`、`src/engine/schedule.ts`：复用现有 `listLongTermTasks` 与统一 7 天边界，不新增第二套日期范围判断。
- `src/assistant/event-store.ts`：修正置顶分组内排序。
- `app/event/[id].tsx`：删除置顶、更多和重命名交互；待办文字取消导航。
- `src/assistant/ui-state.ts`、`src/components/AssistantActionReceipt.tsx`：根据操作快照中的待办日期生成首页 Tab 与定位参数；事件回执继续进入事件详情。
- 对应自动化测试、设计文档和验收话术。
