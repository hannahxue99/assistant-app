# 苹果日历定时时间精度修复设计

状态：已确认，等待实现。

## 问题与现场证据

Release 待办“顾朝希用工商银行信用卡买校服”在 2026-10-05 20:35、20:37、20:38 三次更新中，模型均提交 `2026-10-11 15:00` 与 `timePrecision=dateTime`，协议校验和事务提交均成功。最终 `entries.due_at` 为 15:00，但 `entries.time_precision` 为 `date`，苹果日历因此生成全天日程。

根因是 `syncFtsWithDatabase` 同时承担了全文索引刷新和时间精度推断。小知保存结构化 `dateTime` 后，该函数立即根据不含时刻的待办标题重新推断为 `date`，覆盖已经校验的业务事实。删除系统日历日程不能修复；下一次同步仍会依据错误精度重建全天事件。

## 方案比较与决策

1. **只去掉覆盖，要求用户再次修改时间**：改动最小，但已受影响的 Release 数据继续错误，用户已经重复操作三次，不接受。
2. **按非 09:00 时间猜测定时事件**：能批量修复，但会把历史保留时钟、时区变化或手动数据误判为明确时刻，不符合“绝不以默认时间推断用户意图”的既有原则。
3. **去掉覆盖，并用已提交操作日志定向修复**：推荐。结构化操作日志保存模型提案、校验结果和提交操作 ID，可只恢复有明确 `dateTime` 证据且当前 `due_at` 与提案完全一致的记录。

采用方案 3。范围仅限开始时刻精度；不增加结束时间、时间段或页面交互。

## 数据与实现

- `syncFtsWithDatabase` 只维护 `entries_fts`，不再更新 `entries.time_precision`。
- 规则录入、旧数据升级和手动编辑在各自写入路径显式计算时间精度；小知创建/更新继续以本地校验后的 `storedTimePrecision` 为权威。
- 新增一次性、幂等迁移 `assistant-time-precision-structured-v1`：
  - 仅扫描当前为 `date` 且有日期的待办。
  - 从该待办最近的已提交日期操作向前查找；跳过不改变日期的操作。
  - 同时支持普通 operations 和 event delta 编译出的 todo key。
  - 必须满足：操作仍为 committed、决策日志 committed、操作 ID 在 committed 列表、validation 中对应 key 被 accepted、提案为 resolved/dateTime、按本地时区机械投影的时间戳与当前 `due_at` 完全相同。
  - 满足时只把 `time_precision` 改为 `dateTime`。条目更新触发现有日历补偿队列，更新同一系统日程。
  - 若任何 JSON 损坏、证据缺失、时间不匹配或存在更晚的日期操作，保守跳过。
- 迁移完成写入 `assistant_migrations`，重复启动不重复修改。

## 数据流

`小知 dateTime 提案 → 本地日期校验 → entries 写入 dateTime → FTS 仅更新索引 → calendar_jobs → calendarProjection(allDay=false) → 更新既有 EventKit 日程`

历史修复为：

`启动 → 读取已提交结构化证据 → 精确匹配 due_at → 修复 time_precision → calendar_jobs → 原日程由全天更新为 15:00–16:00`

## 边界与回滚

- 仅日期提案继续保持全天；默认 09:00 不会升级为定时。
- 标题或正文不含时刻，不再覆盖小知的结构化 `dateTime`。
- 手动编辑文字中的明确时刻仍按现有规则更新精度。
- 导入数据保留备份中的精度；老备份缺字段时才按原文保守推断。
- FTS 全量重建和增量刷新均不得改变时间业务字段。
- 修复不新增原生依赖、权限或 Bundle ID；数据库只修正可审计字段，可通过回退代码并将对应条目重新设为全天回滚。系统日历已有事件不主动删除。

## 验收标准

- 小知把不含时间的待办标题改为 15:00 后，数据库保持 `dateTime`。
- 日历投影为非全天、15:00–16:00，并更新原 eventId 而非重复创建。
- 仅日期、默认 09:00、日期与定时互转保持正确。
- FTS 增量刷新和重建不改变 `time_precision`。
- 构造 Release 现场日志后，一次迁移修复目标条目，第二次运行返回 0。
- 损坏日志、不匹配时间和更晚的全天操作均不修复。
- 聚合测试、类型检查与 `npm run ci` 通过；PR 保持待验收，不提前合并。
