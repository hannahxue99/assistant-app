# 小知键盘、贴底与返回路径设计

## 背景

小知输入框是覆盖消息列表的悬浮卡片。当前 iOS 使用 `KeyboardAvoidingView` 的 `padding` 模式，绝对定位的输入框仍锚定原页面底部，键盘弹起后可能被遮挡；消息列表也只在内容尺寸变化时尝试贴底，无法覆盖键盘、输入框多行高度和页面上下文区域导致的可视高度变化。

交互审计还发现，回复完成、停止和重试结束会无条件滚到底部，覆盖用户主动上翻的位置；从小知进入设置和调试页时也没有复用回执跳转的返回位置保护。

## 设计

### 视觉

以 Codex 移动端交互为视觉依据：输入框始终是一张悬浮卡片；离开末端后，输入框上方出现独立圆形置底按钮；白色渐隐和卡片阴影按距离末端的远近连续增强，不形成实色底部面板。

```text
┌────────────────────┐
│ 消息列表             │
│                    │
│        [ ↓ ]       │  仅离开末端后显示
│  ···白色渐隐/轻阴影···│  距离越远越明显
│   [ 小知输入框 ]     │  始终悬浮
├────────────────────┤
│       系统键盘       │  键盘开启时
└────────────────────┘
```

键盘关闭时，输入框仍悬浮在底部 Tab 之上：

```text
│ 最新回复完整可见     │
│                    │
│   [ 小知输入框 ]     │
│      底部 Tab        │
└────────────────────┘
```

### 交互规则

1. 默认进入小知定位到对话末端；点击输入框只让键盘与悬浮输入框一起上移。
2. 消息区高度或输入框高度变化时，只有处于 `following` 的用户继续贴底。
3. 用户主动上翻离开末端后进入 `history`，显示置底按钮；此时点击输入框只拉起键盘，消息位置不变。
4. 只有点击置底按钮、发送新消息或从首页/我的重新进入，才明确回到 `following`。
5. 流式增长、回复完成、停止和重试尊重当前模式，不得把 `history` 用户拉回。
6. 用户滚回末端后自动恢复 `following`，置底按钮与额外阴影一起消失。
7. 从小知进入回执目标、理解引擎或 Dev 决策日志后返回时恢复离开前的位置。
8. 切换 Tab、离开小知或打开搜索来源网页前收起键盘，但保留未发送草稿和消息位置。

## 数据流

- 键盘只改变页面可视高度，不进入业务数据层。
- 页面只维护 `following / history` 一套滚动模式；只有用户手势或明确的“置底/发送/重新进入”动作能切换模式。
- 同一个纯距离计算同时产出“是否贴底、是否显示置底按钮、阴影强度”，避免三个效果不同步。
- 悬浮输入框所需的底部空间使用真实 `ListFooterComponent`，不依赖 `scrollToEnd` 可能忽略的容器 padding。
- 页面高度、输入框高度和消息内容高度变化统一读取该模式：`following` 才在下一布局帧校正到末端，`history` 不操作。
- 输入框聚焦时快照当前模式：`following` 在键盘动画完成后重新校正末端；`history` 只接受视口高度变化，不调用 `scrollToEnd`。
- 刷新消息新增三种策略：始终贴底、仅当前仍在末端时贴底、永不贴底。
- 路由离开前只更新页面内的返回位置标记并收起键盘，不改变消息、草稿或请求生命周期。

## 边界情况

- 单行与多行输入框切换。
- 键盘弹出、交互式收起和快速切换 Tab。
- 长回复流式增长时用户主动上翻。
- 回复完成、停止或重试恰逢用户滚动。
- 事件上下文 Banner 出现或关闭。
- 思考过程、搜索来源和处理回执动态增高消息。
- 请求进行中切换首页，再返回小知。
- 键盘开启状态下继续上滑、点击置底按钮和交互式收起键盘。
- 列表不足一屏、距离末端很近和滚动回弹。

## 验收标准

- 键盘弹起后输入框完整可见，并贴在键盘上方。
- 位于末端时，最新回复最后一行始终位于输入框和渐隐层上方。
- 用户上滑离开末端后显示置底箭头；点击后平滑回到底部并隐藏箭头。
- 在历史位置点击输入框，只拉起键盘，不改变当前阅读位置。
- 白色渐隐和输入框阴影随离底距离连续增强，回到底部后自然消失。
- 用户上翻后，回复完成、停止和重试不改变其位置。
- 首页或我的通过 Tab 进入后显示最新对话；事件详情、设置、调试和网页来源返回后恢复离开前状态。
- 未发送草稿不会因导航或键盘收起而丢失。
- 输入框保持悬浮卡片，不出现独立底部面板；三 Tab 白色背景无变化。
