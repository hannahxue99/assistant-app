# “我的”层级与小知输入体验微调

状态：已实施，等待 Dev 端验收

视觉稿：[前后对比](../../design/profile-composer-voice-refinement-v17.svg)

## 目标与选择

本轮只解决三个明确问题：让“长期记忆 / 设置”更像页面一级结构；降低小知空闲输入框的视觉高度；让用户在语音输入时明确知道麦克风正在工作。它不改变语音转写、消息发送、对话落库或长期记忆的数据链路。

语音反馈比较三个方案：

1. **真实音量波动条（推荐）**：使用当前 `expo-speech-recognition` 已提供的 `volumechange` 事件驱动 5 根短柱，实时反映麦克风输入；同时保留转写文字。反馈真实、改动范围小。
2. 固定循环动画：实现最轻，但即使没有声音也会持续跳动，容易制造“已经听见”的错误感知。
3. 完整音频波形轨道：反馈最丰富，但会增高输入区，并带来更重的动画、采样和性能成本，不适合本轮紧凑化目标。

采用方案 1。

## 视觉与交互规格

### 我的

- “长期记忆”和“设置”字号由 17 调整到 19，字重与颜色不变。
- 右侧“陪伴 X 天 · X 条”和三个设置分组标题维持现有字号，避免所有文字一起变大导致层级再次变平。
- 卡片尺寸、卡片正文和模块间距不扩大。

### 小知输入框

- 单行空闲高度由 58 收紧到约 50；圆角、边框和阴影同步收紧。
- 麦克风与发送按钮的可见圆形由 44 收紧到 38～40，但使用 `hitSlop` 保持至少 44×44 的可点击区域。
- 单行输入区减小上下内边距；多行仍向上增长，最大约五行，不牺牲长文本输入。
- 小知处理中继续使用已确认的“清空、置灰、不可输入”，不增加第二个转圈。

### 语音状态

- 点击麦克风后，左侧切换为停止按钮；其右侧出现 5 根橙色短柱。
- 短柱由真实音量驱动：低于可听阈值时保持细微静止高度，有声音时按音量变化，并做轻量平滑以避免抖动。
- 实时转写仍出现在同一个输入框中；波动条只占一小段横向空间，不额外增加输入框高度。
- 右侧弱提示显示“正在听”；再次点击停止后，波动条和提示消失，转写文字保留且可编辑。
- 权限拒绝、识别错误、切换 Tab、处理中终止识别等现有逻辑保持不变；结束或异常时音量立即归零。

## 实现与数据流

- `MemorySection` 与 Profile 的一级标题使用同一个 19px 规格。
- `AssistantComposer` 监听现有语音模块的 `volumechange`，启动识别时开启音量事件；以本地瞬时 UI 状态渲染 `VoiceLevelBars`。
- 音量状态不进入数据库、不进入消息、不发送给模型，也不保存录音。
- 不新增依赖、不改原生权限或 Bundle 配置；当前 Dev Build 可通过 Metro Reload 验证。

数据流：`麦克风输入 → 系统语音识别 → volumechange → 本地波动条`；同时 `result → 输入框实时文字 → 用户停止/编辑 → 发送`。两条 UI 数据流互不阻塞。

## 边界与验收标准

1. “长期记忆”和“设置”视觉字号一致，均明显大于设置分组，但不挤压右侧陪伴摘要。
2. 小知空闲输入框明显低于当前版本；按钮仍容易点击，文字不被裁切。
3. 长文本仍可增长到约五行；键盘、发送、处理中的既有行为不变。
4. 开始语音后立刻出现波动条；安静时弱波动，说话时随真实音量变化。
5. 语音实时文字继续回显；停止后文字保留、可编辑、不自动发送。
6. 语音失败或离开页面后不残留波动条，也不产生额外消息或录音文件。
7. 补充音量归一化和语音 UI 状态测试，并纳入现有 `npm test`；完整 `npm run ci` 通过后在当前 Dev App Reload 验收。
