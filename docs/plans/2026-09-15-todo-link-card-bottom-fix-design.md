# 首页待办跳链与事件卡底部留白修正

状态：已确认并实施，等待 Dev 真机验收

视觉稿：[跳链切换与事件卡底部留白修正](../../design/todo-link-card-bottom-fix-v15.svg)

## 现象与根因

### 1. 从小知进入“全部待办”后，无法切回“本周待办”

小知回执通过 `todoView=all&focusTodoId=...` 让首页首次打开“全部待办”并定位目标。当前首页的监听逻辑在组件状态变化后还会重复读取同一组跳链参数；用户点击“本周待办”时，旧参数又把页面改回“全部待办”。

### 2. 事件卡底部留白过大

事件卡的外层和内容层都设置了固定最小高度。三行内容已经改为连续排列，但固定高度仍在底部留下额外空间。

## 推荐方案

### 跳链只作为一次性进入意图

把 `todoView + focusTodoId` 组成一次跳链意图。首页只在第一次看到这个意图时执行三件事：选择目标 Tab、滚动到目标待办、短暂高亮。意图消费完成后，当前 Tab 完全由用户点击决定；组件因布局或状态变化重新渲染时，不再重复应用旧参数。

后续从小知点击另一条回执，会形成新的跳链意图并再次准确定位。现有滚动、高亮、7 天边界和两个列表互不重复的规则都不变。

### 事件卡由三行内容自然撑高

移除卡片和内容区的固定最小高度，保留标题、进展、时间三行及一致的上下内边距。目标视觉高度约 86–90px；标题与进展仍各限制一行，空进展继续显示占位，因此同类卡片高度仍稳定。置顶按钮的 44px 点击热区不变。

## 实现与数据流

1. 在纯 UI 状态模块中标准化跳链意图并生成稳定 key，首页用它判断是否已消费；为重复参数和新参数补回归测试。
2. 首页监听到新意图时更新 Tab 和定位状态；监听到已消费意图时直接返回，不再覆盖用户的手动选择。
3. 事件卡只调整布局样式：去掉 `minHeight`，缩小并统一三行间距和上下内边距。
4. 不新增或迁移 SQLite 字段，不修改待办/事件数据，不改变小知模型调用和落库流程。

## 不采用的方案

- 进入首页后主动清空路由参数：会修改浏览历史语义，也更依赖路由更新时机。
- 完全取消跳链参数对 Tab 的控制：会失去小知回执准确落到“全部待办”的能力。
- 继续微调固定高度：不同字号和系统字体设置下仍可能重新出现底部空白。

## 边界情况

- 同一条回执因重新渲染多次：只消费一次。
- 用户消费跳链后手动在两个 Tab 间来回切换：选择保持，不被旧参数覆盖。
- 后续点击新的小知回执：新的目标 id 形成新意图，可以重新切换并定位。
- 目标待办已经完成或不存在：目标 Tab 仍可进入，但不滚动、不高亮，也不报错。
- 事件标题或进展过长：各自单行省略，卡片高度不跳动。
- 事件没有进展：显示现有占位语，仍保持三行。
- 系统动态字体放大：内容可以自然撑开，不被固定高度裁切。

## 验收标准

1. 从小知的远期待办回执进入“全部待办”，再点“本周待办”，页面稳定停留在本周列表。
2. 手动来回切换两个待办 Tab 均正常；无上下浮动、无下划线。
3. 再从小知点击另一条待办回执，仍能进入正确 Tab、滚动并高亮目标。
4. 事件卡稳定显示标题、进展、时间三行，底部无明显多余留白，上下内边距视觉一致。
5. 置顶按钮、事件排序、事件详情跳转和待办数据范围保持不变。
6. `npm run ci` 通过，并在当前 Dev App 中 Metro Reload 后完成真机验收。
