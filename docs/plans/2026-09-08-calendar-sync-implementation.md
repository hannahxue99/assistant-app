# 苹果日历同步实现与验收

## 实现

- Expo 57 新版 Calendar API，通过 CalendarNext 可用性检查兼容尚未重装的旧 App；仅 iOS 展示入口。
- 我的开关默认关闭，首次说明历史同步范围，系统完整访问授权后选择可写账户；拒绝权限不影响记录。
- 专用日历名以“私人助手”开头，追加8位本机标识区分同名日历及恢复创建中断，界面显示“私人助手专用日历”。只认保存的calendarId和事件URL来源标记。
- SQLite triggers 在新增、任何回填/修改、删除事务中写calendar_jobs。删除不清calendar_links，直到系统日程删除成功。
- 单例串行worker每批50条，前台5秒检查持久队列，失败任务60秒后重试，启动/前台/主动重试对账；关闭与写入串行，关闭返回后不会继续写。
- entryId到eventId映射保留last_due/attempt_due，在系统写成功但SQLite落库失败后以来源标记找回事件。generation条件确认避免旧任务清掉新修改。
- 全天结束日期使用本地日历加一天。明确时刻默认占位1小时；事件无额外alarm。完成用✓，正文放备注。
- time_precision新增可空列，旧数据依原文明确时刻且匹配dueAt才判定定时；备份仍兼容V2并可携带可选timePrecision，设备映射与授权状态不导出。

## 自动验收

`npm run test:calendar` 用真实内存SQLite执行db与worker，模拟系统日历。覆盖关闭、第一次创建、失败找回不重复、文字更新、完成撤销、撤销权限、并发写入、关闭期间删除、历史过滤、全天/定时/跨月、队列回滚。
运行typecheck与其余package.json全部测试。安装ExpoCalendar Pods后构建Release真机包。

## 手机验收（待用户确认）

1. 覆盖安装后，进入我的，开启同步，允许完整访问并选择账户。
2. 打开苹果日历，勾选私人助手专用日历。
3. 新增“明天买牛肉”，应为明天全天；“明天下午3点看牙医”应为15–16点。
4. 修改标题/正文/日期，原日程更新且没有重复；完成加✓、撤销完成去✓。
5. 删除或清除日期，对应日程被删除。
6. 关闭同步后编辑/删除，日历不变；重新开启后补偿。
7. 拒绝权限时待办照常保存；恢复权限后点重试可补同步。

## 边界

- 单向同步：在苹果日历里改动不会反向修改记录；下次对账以私人助手为准。
- 原日历删除或账户不可写时暂停，不自动新建日历或认领其他日历；用户需恢复账户/原日历后重试。
- 本机映射不跨设备复用。同一备份在另一手机开启同步会建立该手机独立日历。
- 系统日历的实际授权、账户配置、iCloud送达、系统默认提醒行为只能真机验收，自动测试不宣称其通过。
- 首次同步只导出今天及未来未完成待办；已关联任务即使后来逾期/完成仍维护。

## 构建与回滚

ios目录未纳入Git。app.json记录权限插件；现有原生工程通过pod install并在Info.plist补NSCalendarsUsageDescription/NSCalendarsFullAccessUsageDescription，保持原Team与Bundle ID，不运行破坏签名配置的全量prebuild。
需要Release覆盖安装，Reload无法增加原生日历模块。上线前用户真机验收。回滚先关闭同步，再回退PR并覆盖安装；新增表列保留兼容旧库，不自动删除系统事件。
