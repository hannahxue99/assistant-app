# 小知 DeepSeek 原生联网搜索 P0 设计

状态：已确认，进入实施

## 1. 目标与边界

P0 解决“小知遇到 Muse 是什么、近期发生了什么等外部或时效问题时完全无法回答”的基础能力缺口。用户仍只需自然提问，不选择联网模式；DeepSeek 判断是否需要搜索，并使用 DeepSeek 官方 Anthropic Messages 接口的 `web_search_20250305` 服务端工具完成搜索、结果内容读取和初步归纳。

P0 不接入 Tavily、豆包或独立网页正文抓取服务，不实现 `open_web_page`，不承诺逐句引用已经和某一网页原文精确绑定。小知展示 DeepSeek 本轮返回的搜索来源标题与 URL，名称使用“搜索来源”，不伪装成精确 citation。

搜索次数、服务端返回结果数量和 DeepSeek 读取的结果数量不设置产品级硬上限，由 DeepSeek 服务端自行决定。现有请求超时、用户停止、重复工具循环保护继续作为系统保险，但不向用户表达为网页数量限制。

## 2. 采用方案

保留现有 OpenAI Chat Completions 主对话协议和本地只读工具循环，新增一个由主模型按需调用的 `web_search` 只读工具。该工具不接第三方搜索引擎，而是使用同一份本地 DeepSeek Key 调用：

`https://api.deepseek.com/anthropic/v1/messages`

工具请求启用 DeepSeek 的 `web_search_20250305` 服务端工具。DeepSeek 服务端自行拆分搜索词、执行搜索、读取其加密结果内容并生成搜索摘要；小知解析返回的 `web_search_tool_result`，保留标题与 URL，再把摘要和来源交回主模型形成最终自然回复。

选择这一结构而不是把整个小知运行时切到 Anthropic 协议，是为了复用现有流式回复、本地事件/待办/记忆工具、JSON 操作协议、停止、重试和安全校验，避免 P0 重写已稳定的主链路。

## 3. 数据流

```text
用户自然提问
→ 现有 DeepSeek 主模型判断是否需要外部实时信息
→ 不需要：沿用现有本地对话与工具流程
→ 需要：调用小知的 web_search 只读工具
→ web_search 使用同一 DeepSeek Key 调用 Anthropic Messages API
→ DeepSeek 服务端自主搜索、读取结果并返回摘要与来源
→ 小知把摘要和来源交回主模型
→ 主模型生成最终回答
→ 小知保存回答和本轮搜索来源并展示来源卡
```

网页搜索执行期间，运行状态显示“正在搜索网页”；搜索工具返回后显示“正在整理”。用户点击停止时复用现有 AbortSignal，终止当前主请求或搜索子请求，未完成轮次不提交业务变化。

## 4. 数据与界面

设置新增 `webSearchEnabled`，默认开启。它复用理解引擎的 Base URL、模型与 Key，不增加第二份凭证。“我的”页在“理解引擎”下增加“联网搜索”入口；设置页只提供开关、DeepSeek 服务状态和跳转到理解引擎配置。

每条助手消息可以关联零到多条搜索来源：`title`、`url`、`position`。来源单独保存在 SQLite，并与 request 关联；不保存 DeepSeek 返回的 `encrypted_content`。消息卡默认折叠“搜索来源 N”，展开后显示全部有效来源。点击来源只允许 `http` / `https` URL，并使用 Expo SDK 57 的 `WebBrowser.openBrowserAsync` 打开。

搜索来源属于联网回答的辅助证据，不进入长期记忆，不被当作本地事实或用户授权。备份需要保留消息与来源的关联，恢复后来源卡仍可查看。

## 5. 安全与失败处理

- 只有 DeepSeek 官方 Base URL 才启用 P0 搜索；自定义兼容服务显示“不支持联网搜索”。
- 网页内容和搜索摘要视为不可信外部输入，不能指示小知调用本地写操作。
- 只要本轮实际使用网页搜索，事件、待办和长期记忆写入一律不在该轮提交；如用户确有写入意图，小知先回答搜索结果，再请用户确认下一步。
- 无有效 URL 的结果不进入来源列表；来源按 URL 去重，但不人为截断数量。
- 服务端搜索失败、返回结构异常或超时，以结构化工具错误交给主模型；最终明确说明本轮未完成联网，不把模型旧知识伪装成实时结果。
- 用户停止后不自动重试，不保存未完成的搜索来源。
- DeepSeek 当前不稳定提供结构化 citations，因此 P0 不生成虚假的 `[1][2]` 逐句引用。

## 6. 验收标准

1. 开启联网搜索后，问“Muse 是什么”时 DeepSeek 可以自主调用搜索并返回回答。
2. 普通本地记录、事件、待办和记忆问题不因联网能力增加额外搜索。
3. 搜索期间显示“正在搜索网页”，现有停止按钮可以终止请求。
4. 完成后消息下方可展开“搜索来源”，展示本轮全部有效标题和 URL，并能在系统浏览器安全打开。
5. 重新进入 App 后，历史消息的搜索来源仍然存在；完整备份往返后仍可恢复。
6. DeepSeek 搜索失败时明确降级，不展示空来源卡，不伪造实时结论。
7. 搜索结果不能直接创建或修改事件、待办、记忆；搜索轮不会提交本地写操作。
8. “我的”页存在独立“联网搜索”入口，复用理解引擎 DeepSeek 配置，不要求额外 Key。
9. 现有小知流式回复、重试、停止、本地工具和操作回执回归通过。
10. 新增测试进入聚合 `npm test`，最终 `npm run ci` 和 GitHub `CI / validate` 通过。
