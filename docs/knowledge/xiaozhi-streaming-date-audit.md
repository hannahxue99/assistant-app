# 小知流式回复、模型日期与决策审计

## 背景与结论

“下个月 10 号还”只显示更新事件，最终页面无法判断究竟是模型没有提出待办，还是待办在本地被过滤。根因包括两层：小知旧协议只让模型抄日期原文，本地中文规则不支持“下个月 N 号”；系统又只保存成功操作，没有保存模型候选与拒绝原因。

现行方案改为：同一次模型调用分别判断事件与待办，并把自然语言日期解析成用户本地日期字段；本地不再重新理解日期原文。回复通过 SSE 流式显示，但完整 JSON 仍须通过协议、本地校验和 SQLite 事务后才生成成功回执。每轮另存一份有界的结构化决策日志，区分模型提议、校验和提交结果。

## 关键取舍

- 事件与待办是两个独立判断，不是互斥分类；代码不得因出现未来日期而自行补建待办。
- 模型输出 `date_status`、`date_text`、`due_date`、可选 `due_time` 和 `time_precision`。本地只拒绝无效格式、无效日历日期和字段矛盾。
- 仅日期机械投影到本地当天 09:00 并保存 `time_precision='date'`；明确时刻保存 `dateTime`。这是存储约定，不是语义解析。
- JSON Output 继续保证一次调用同时返回回复和操作。流式阶段只从未完成 JSON 的首个 `reply` 字符串中提取可见文字，操作必须等完整响应结束。
- 日志不保存 API Key、Authorization、完整系统提示词或重复的完整对话；用消息/上下文对象 ID 回溯事实，保留最近 500 轮。

## 可复用实现模式

1. 使用 Expo 57 默认的 WinterCG `fetch` 读取 SSE `ReadableStream`，按行重组 `data:` 事件，同时处理任意字节拆包。
2. 流式 UI 使用临时助手消息，不提前写事实表；成功后用事务保存的正式消息替换，失败则移除临时消息并保留用户原话重试。
3. 将模型日期结构与存储投影隔离：`protocol.ts` 管字段形状，`model-date.ts` 管日历有效性和本地时间投影，`action-validator.ts` 管对象权限与业务约束。
4. 决策日志按 request ID 幂等覆盖重试；每次重试清空旧候选、校验、耗时和错误，避免新旧证据混杂。
5. 开发控制台只输出操作类型、拒绝原因、耗时和 token 数；持久日志保存结构化候选，足够判断模型是否真的提出待办。

## 易错点

- 不能在收到响应头后清除超时计时器；流式正文读取也必须受同一个超时和取消信号约束。
- JSON 字符串可能跨 chunk、包含转义或 Unicode 转义；流式展示解析器只用于预览，最终结果必须再次走完整 JSON 协议解析。
- 模型判断 `ambiguous` 时可以创建隐藏待办，但不能用含糊日期覆盖已有待办的明确日期。
- 日志失败不能阻断回复或业务事务；反过来，业务事务失败必须在日志中落为失败，不能显示成功回执。
- 按 token 逐个触发 React 渲染会拖慢长列表；UI 更新至少做约 40ms 节流，并在流结束时强制送达完整回复。
