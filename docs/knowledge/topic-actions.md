# 聚合主题操作与编辑一致性

## 产品决策

- 聚合主题卡在 iOS 使用原生 SF Symbols `pin` / `pin.fill`，不再通过旋转 Ionicons 模拟苹果图钉；Android/Web 使用 `push_pin`。线框为未置顶，实心为已置顶。
- 置顶主题优先展示，多个置顶按最近置顶时间排序；取消后按最新消息时间回归普通区。
- 主题允许改名；目标名称已存在时，经确认后合并全部历史消息。
- 全 App 编辑入口遵循“铅笔进入、同位置完成退出”，字号可随页面级或模块级适配。

## 实现经验

- 置顶是主题级展示偏好，应独立存储，不应重复写入每条消息。
- 主题改名与置顶偏好迁移必须在同一事务中完成，避免出现消息已改名但置顶状态遗失。
- 交互一致性应通过共享组件约束，而不是仅靠设计文档约定。
- 图标视觉尺寸可以随层级变化，但触摸区域应保持至少 44×44。

## 验证与回滚

- 自动验证：TypeScript 类型检查、主题排序测试及既有回归测试。
- 手机验收：置顶/取消、多个置顶排序、主题改名、同名合并、编辑返回保护。
- 视觉验收不能只看图标名称：必须核对实际方向、选中/未选中状态，并确保 44×44 点击区采用绝对定位，不撑高内容行。
- 字体图标的原始朝向不能靠名称或记忆推断；涉及旋转时必须以真机渲染结果校准，避免把斜向图标转成横向。
- 设计稿指定平台原生符号时，代码应直接使用同一符号源；“相似图标 + 旋转”不能保证轮廓一致。
- 图标由共享组件集中定义方向、状态和平台映射；设计稿、组件预览页和业务页面必须指向这一个规范，禁止各自复制实现。
- 回滚点：功能 PR 合并前的 `main` 基线 `c98d1d0`。
