# 原声一致性、主题规模与空白安装

## 产品决策与实现模式

- 相对日期重试沿用创建时间，正文编辑以保存时间重新解析。这里记录的早期“仅改标题不改变待办日期、正文变化时生成规则标题”已被 2026-09-08 的[原声编辑与待办日期强一致性](entry-date-edit-consistency.md)取代；现行规则以 `dueAt` 为唯一日期并在用户一次确认后同步标题与正文。
- 模型请求跨越人工编辑、主题改名时可能过期。使用 revisionAt 与原文条件写入，并检查影响行数；本地版本单调递增以防同毫秒修改漏判。失败降级同样受保护。
- 原声、派生待办、FTS 和通知补偿在独占事务内保存，任何一步失败整体回滚。
- 启动串行恢复 failed/pending，单条请求去重，完成后通知首页刷新；保留搜索条件并忽略过期查询。
- 全库按主题计数后读取每组最新一条。不要先截断原声再分组，否则旧置顶消失、卡片数量不准确。列表使用 count/latest，详情按主题加载。
- 一次性个人迁移不可保留在通用启动链路。移除个人种子源码，空库从零记录开始；已落库记录不删除，历史代码可从 Git 恢复。
