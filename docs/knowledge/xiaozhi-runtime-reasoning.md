# 小知推理运行状态与可查看思考

## 背景与结论

Release 环境的 DeepSeek 请求曾在模型仍持续返回推理数据时被固定 45 秒超时中止，C 端又不展示 `reasoning_content`，用户只能看到无变化的等待状态。现行方案将“首包、流空闲、总时长”分开计时，显示连续运行时间，并把 DeepSeek 思考过程作为默认折叠、用户可主动展开的模型产物。

同步收口的 C 端规则包括：历史消息按本地自然日分组，气泡内只显示时分；用户、助手和思考文本都可使用 iOS 原生长按菜单复制；输入区移除额外底栏层，仅保留圆角输入框。

## 关键取舍

- 模型请求显式开启思考模式并设置 `high` 推理强度，不依赖服务端默认值。
- 超时分为 45 秒无首包、30 秒无新流数据和 180 秒总上限；`reasoning_content` 到达也是有效活动，不能被误判为卡死。
- 思考正文放在独立 `assistant_reasoning` 表。历史列表只读取“是否存在、开始和结束时间”，展开时才按 request ID 加载正文。
- 思考文本不进入下一轮模型上下文，避免 token 放大和把模型中间过程当成用户事实。
- 取消自动二次模型请求。格式或业务协议失败保留原消息，由用户点击重试再发起一次完整请求。
- 输入区只移除外层分隔线和可见背景，不改成悬浮覆盖，以免最后一条消息被遮挡。

## 根因、易错点与可复用模式

1. 流式请求的“返回响应头”不等于“业务完成”。超时器必须在读流期间按字节块刷新，同时保留独立总上限。
2. DeepSeek 先返回 `reasoning_content`、后返回 `content`。两者要分别累积，否则思考文本可能混进用户可见回复或被丢弃。
3. 流式临时消息与 SQLite 正式消息合并时，要保留当前进程的运行时间和思考元数据；成功后再用事务内的正式数据替换。
4. JSON Object 只保证 JSON 语法，不保证 `segment.action` 等业务枚举合法。决策日志要能区分网络、超时和协议校验；对话正文和密钥不应进日志。
5. 历史时间分组应比较本地日期键，不能用固定 24 小时毫秒差推算“昨天”，否则夏令时边界会出错。
6. 单层输入区的外层 View 仍可承担安全间距和错误文案布局；“不可见”不等于必须删除结构。
