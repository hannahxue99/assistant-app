# 详情页点击内容编辑

## 产品决策

- 用户原声详情浏览态不显示铅笔。标题、正文及其下方剩余内容画布构成一个连续点击区，点击后进入编辑态。
- 返回栏、时间信息和删除操作不属于编辑点击区。
- 用户原声编辑态始终提供标题、正文两个独立输入框；右上“完成”统一提交。即使初始标题与原文相同，也不能把两者继续绑定，否则改标题会覆盖原文。
- 聚合详情浏览态不显示铅笔；点击主题标题原位编辑，失焦或键盘确认时自动保存，不显示“完成”。

## 根因与取舍

最初只把点击事件绑定到标题和正文文字组件，导致视觉上属于内容区的大片空白无法点击。修复方式不是简单扩大文字的 `hitSlop`，而是让承载标题、正文和剩余空间的容器整体成为 `Pressable`；这样点击范围与用户感知的“内容画布”一致。

聚合主题的失焦和键盘确认可能连续触发保存，因此使用进行中标记保证一次编辑只提交一次。主题正在编辑时暂时阻止消息卡跳转，避免失焦保存和页面导航发生竞态。

## 验证方式

1. 点击原声标题、正文及正文下方空白，均应进入编辑。
2. 点击时间、返回和删除，不应进入编辑。
3. 在页面滑动，不应误触编辑。
4. 标题与原文相同时进入编辑，分别修改后应各自保存。
5. 聚合主题分别通过键盘确认和点击空白保存，均只执行一次；重名与空主题仍走原校验。

## 回滚点

回滚 PR #6 即可恢复右上编辑按钮和文字级点击区域；本次没有数据库结构迁移。
