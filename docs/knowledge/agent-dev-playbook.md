# Agent 开发实战手册——图标重设计全程复盘

> 面向后续接手本仓库的 AI agent：这波开发踩过的坑、走通的路径、该有的工作方式，都在这里。项目事实类知识分散在各专题文档（见 INDEX），本文只讲**过程经验和决策方法**。案例背景：App 图标重设计（PR #16，2026-09-09，从提案到真机定稿三轮迭代全程约 4 小时）。

## 一、开发环境铁律（违反必失败）

1. **本机 git https 传输不可靠**：`git push`/`fetch` 会无限挂起（疑 Clash 代理干扰 443 大流量），但 `gh api` 通道正常。推送失败时**不要反复重试**，直接走 GitHub API 四步：blob 上传（`base64 | jq | gh api git/blobs`）→ 组 tree（基于远端 HEAD 的 base_tree）→ 建 commit → PATCH ref。见 `github-ci-and-git-toolchain.md`。
2. **必须用 `/usr/bin/git` 2.50.1**（AGENTS.md 规定）：PATH 里的 `/usr/local/bin/git` 2.6.4 是 Xcode 附带旧版，会半途挂起且难察觉——`ps aux | grep git` 看到 `/Applications/Xcode.app/.../git` 就该杀掉重来。
3. **expo CLI 设备识别两种 ID**：`devicectl` 的 coredevice UUID（15988BB1-…）expo 不认，要用 `xctrace` 的 UDID（00008150-…）或设备名；设备名解析偶发失败，UDID 最稳。锁屏只影响「自动启动」，不影响安装——装上了就是装上了。
4. **Metro 隧道是手机联网前提**（Mac 在 11.x 企业内网）：`npx expo start --tunnel --dev-client`，地址每次重启都变。Debug 版 App 没有它就是砖。
5. **prebuild 后必查两处**（详见 `app-icon-redesign.md`）：`ios/app/app.entitlements` 被写回 `aps-environment` 要清掉；签名配置可能被重置。

## 二、真机验收方法论（这是本案最大教训）

**「装上手机 ≠ 验证完成」**。本案三轮迭代全部由真机反馈驱动——模拟器/浏览器预览全绿的东西，真机 60px 上一塌糊涂。核心经验：

1. **先确认手机上跑的到底是什么**：本次「图标没变」的排查，从「原生工程里的图还是旧的」→「手机装的是 9 月 4 日旧构建」→「截屏数值分析显示勾粗细匹配旧版」层层递进。**每次构建装机后用产物校验**（`Assets.car` 时间戳、取样像素色值），不要假设。
2. **无图像识别时用数值分析代替目检**：四角取色验出血、勾质心坐标验居中、橙像素占比验存在感、WCAG 对比度公式验「虚不虚」、截屏勾宽/图标宽比值识别新旧版本。Pillow + numpy 十几行代码的事，比「再装一次看看」可靠得多。
3. **小尺寸视觉问题的诊断顺序**：占比 → 对比度 → 信息密度。「糊」不一定是分辨率问题，本案真根因是品牌橙对纸底对比度只有 1.72:1（加深一档到 2.03:1 解决）；格线灰雾是第三层。**别在第一层假设上反复调参**。
4. **用户反馈「不对劲」时先量化再动手**：用户说「虚、不实，不是大小问题」——一算对比度立刻定位。用户说「没居中」——一算质心发现 bbox 对齐偏了 (54,79)px。主观反馈 + 客观量化 = 快速收敛。
5. **平台限制先行验证**：「按尺寸出图标」在本项目不可行——iOS 26 appiconset 只认单一 1024px（actool 实测）。先花 10 分钟验证平台能力，再设计方案，避免整个方向返工。

## 三、设计协作流程（走通了的一套）

1. **提案先行**：四方向提案（含论点/优劣/真机尺寸条/对比矩阵/推荐）→ 用户选方向。设计文档 = HTML（`design/*.html`），双主题、含 60px/29px 等比缩放列——**用户在浏览器里缩小窗口看小尺寸列**，比口头描述高效百倍。
2. **备选稿永远比单稿快**：意境探索一次出三稿（纸影/光晕/细线三方向），用户说「都不太行，加细线呢」→ 再出三稿细线版。方向性反馈比精度反馈值钱，一次给多个可对比的方向。
3. **设计决策要可追溯**：每次定稿/改稿的理由写进 commit message 和知识文档（本案三轮迭代的「反馈→修订→根因」表格）。半年后想知道为什么是 `#C95F28`，不用考古聊天记录。
4. **设计资产参数化**：`scripts/generate-icons.py` 把勾形贝塞尔、臂宽、三行线、颜色全做成参数——三轮迭代全是改数字重跑，从未手工改图。任何视觉资产都该这样。

## 四、发布形态认知（用户常混淆的点）

| 形态 | 特征 | 适用 |
|---|---|---|
| Debug dev-client | 壳 + Metro 实时代码 | 开发期，改码秒级生效 |
| Release 包 | JS 内嵌、离线独立 | 日常使用——用户「打开直接进首页」的需求指它 |

- Release 覆盖安装保留数据（同 bundle ID）；**删除重装才丢数据**（SQLite 沙盒），删装前必须先 App 内导出。
- 免费证书 7 天过期是硬规则，到期重签 = 连 Mac 覆盖安装一次。
- 用户说「App 打不开/要加载页」时，先分辨他要的是哪种形态，别在 Debug 模式里折腾「去启动页」。

## 五、流程纪律的取舍（本案的实际执行偏差）

AGENTS.md 规定「用户验收 → 知识沉淀 → PR 合并」，本案曾抢跑被用户叫停——**这是对的修正**。经验：

1. 涉及真机验收的变更，PR 开着等验收，别自行推进合并；用户说「可以了」再走收尾。
2. 知识沉淀放在合并前（合并后写 PR 描述引用它，信息最完整）。
3. 中途给用户的状态同步要「已完成 / 正在做 / 等你做什么」三段式，长任务（构建 5-15 分钟）主动告知预期时长。
4. 一次探索失败就换路径（actool 走不通 → 直接放弃多尺寸方案改单图优化），不在死胡同里证明自己能钻过去。
