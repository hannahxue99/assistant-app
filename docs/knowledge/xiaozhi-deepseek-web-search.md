# 小知 DeepSeek 原生联网搜索与 Agent 对话层级

## 背景与最终决策

小知原先只能依赖本地记录和模型固有知识，遇到陌生实体、外部事实或最新动态时无法可靠回答。P0 直接复用现有 DeepSeek 配置与服务端原生 `web_search_20250305`，不引入 Tavily、豆包搜索或独立网页正文抓取。

最终产品规则：

- DeepSeek 服务端自行决定是否搜索、搜索次数、结果数量和读取范围；小知端不设置固定 3 次、12 条或按问题类型分配网页数。
- 联网搜索只用于回答。同一轮一旦使用网页搜索，禁止创建或修改待办、事件和长期记忆；需要执行时由用户下一轮明确确认。
- “我的 → 联网搜索”只保留标题和“允许小知联网搜索”开关，切换即保存。
- 搜索来源随助手消息持久化并进入完整备份；界面展示来源标题、域名和安全 URL，不伪造逐句引用。
- 用户消息与小知最终回复使用气泡；思考、搜索和来源是无底色的中间状态；真实处理结果使用独立紧凑卡片。
- 输入框作为悬浮卡片覆盖列表，滚动时从输入框上沿到 Tab Bar 上沿使用白色渐隐；最后一条消息保留足够滚动空间。首页、小知、我的和 Tab Bar 使用统一纯白背景。

## 实现与数据边界

- Provider 继续使用 Anthropic Messages 兼容协议，在官方 `https://api.deepseek.com` 地址下向模型暴露 `web_search`，本地执行器再调用 DeepSeek 原生搜索工具。
- 同一参数的搜索在单轮内复用 Promise，避免模型重复调用造成并发重复请求；不把这个去重误当成搜索次数限制。
- `assistant_web_sources` 以 request ID 和 position 保存标题、URL 与创建时间；`settings.web_search_enabled` 是默认开启的增量字段。
- 搜索结果属于不可信外部输入，只能进入回答生成。Orchestrator 在提交前清空联网轮提出的 operations、event deltas 和 memory deltas，并记录只读拒绝原因。
- 来源打开前只接受无凭据的 HTTP(S) URL；非法、本地协议或带用户名密码的地址不能交给系统浏览器。
- V3 完整备份包含搜索来源；上线前旧 V3 文件缺少来源字段时仍可导入，增量表和设置字段不要求破坏性迁移。

## 交互取舍与踩坑

1. 搜索次数不应由客户端硬编码。DeepSeek 已拥有服务端搜索规划，客户端只负责安全边界、状态展示、持久化和成本观测。
2. “来源入口”和“思考入口”需要相同的信息层级：蓝色图标、灰色文字、紧邻箭头，无满宽胶囊和套娃卡片。
3. 最终回复与处理回执职责不同。回复使用阅读气泡；回执承担跳转和撤销，保持独立卡片更易识别，但标题和结果文字需左对齐、压缩无意义底边距。
4. 悬浮输入区不能用整块不透明底板遮住列表。正确效果是卡片自身阴影，加一层仅从输入框上沿向 Tab Bar 渐白的背景；渐隐延伸到输入框上方会让用户误以为内容消失。
5. React Native 0.86 可用 `experimental_backgroundImage` 渲染原生线性渐变，无需为这个视觉效果新增原生依赖或重装 Dev 壳。
