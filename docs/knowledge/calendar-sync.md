# 日历同步：实现模式与验收边界

状态：2026-09-08 随 PR #14 首次发布；2026-10-05 定时时间精度与 EventKit 模式切换修复经真机验收，随 PR #37 发布。

## 决策与风险

日历为私人助手待办的单向副本，日期来自dueAt，全天/定时另存time_precision，不以默认9点推断时刻。专用日历及来源URL限定所有权，不能按通用同名标题认领日历。UI说明账户及iCloud同步影响。

## 可复用模式

记录事务通过SQLite触发器持久化意图，原生API在提交后执行；删除保留墓碑。系统日历和SQLite无法构成同一事务，因此保存attempt_due及稳定标记，找回创建成功但映射落库失败的事件。队列generation条件确认防止旧回调覆盖新任务。单例串行执行包含开关，失败退避，不阻塞记事。

时间精度属于待办事实，不属于全文索引投影。模型已经提交 `dateTime` 后，FTS 增量刷新或重建都不得根据不含时刻的标题重新推断并覆盖它。规则录入、模型提交、手动编辑、撤销和导入必须在各自的事实写入边界明确维护精度；历史错误只能依据已提交、已校验、时间戳完全匹配的结构化操作证据修复，不能因为 `due_at` 不是默认 09:00 就猜测用户意图。

EventKit 的全天/定时标记会改变开始、结束字段的解释方式。Expo SDK 57 Calendar Next 更新既有日程时，iOS 原生层先写日期，最后写 `isAllDay`；把既有全天日程的 `allDay=false` 与 15:00–16:00 放在同一次更新中，系统可能仍按旧全天语义把结束时间归一到 00:00。可靠做法是先只提交模式标记，按原 eventId 重新读取并校验所属日历和来源 URL，再写完整日期字段。两个阶段全部成功前不得确认同步任务；第二阶段失败后，下一次重试可在新模式下补齐字段，不删除、不重建、不产生重复日程。定时改全天也采用相同保护。

## 坑

Expo 57日历默认入口是新版类API，旧Async函数从默认入口调用会抛错，不能照搬旧示例。旧二进制不含CalendarNext时应显示需要更新而不是启动崩溃。新增原生模块要重装，JS打包成功不能代替设备验收。
日期、明确小时、系统默认小时要分开。实测本项目通过 Expo Calendar Next 写入 EventKit 时，全天事件若使用“次日 00:00”作为结束时间，苹果日历会把它展示在两天；必须把结束时间限制在同一自然日的 23:59:59.999。专项测试要同时覆盖普通日期和月末，不能只断言时间跨度。
Mac 日历中显示正确不能代替 iPhone 验收。PR #37 首轮 Release 在 Mac 侧看似正常，但 iPhone 截图明确显示目标事件从 15:00 延伸到 00:00，最终依靠真机证据定位到 EventKit 模式切换顺序。验收必须检查手机事件块的实际结束位置、原 eventId 和重复数量。
备份只保存记录时间精度；授权、eventId、calendarId和同步队列是设备本地状态，不能随备份跨设备复制。

## 2026-10-05 PR #37 发布记录

- 目标：让有明确时刻的待办同步为定时日程，并安全修复 Release 中已被覆盖成全天的记录；不增加结束时间交互，定时日程继续默认占位一小时。
- 实现：FTS 改为纯投影；新增基于已提交结构化证据的幂等精度迁移；全天与定时形态变化使用两阶段 EventKit 更新并保留原 eventId。
- 自动验证：`npm run test:assistant-actions-db`、`npm run test:calendar`、`npm run typecheck` 和 `npm run ci` 通过；GitHub `CI / validate` 通过。回归覆盖 15:00–16:00、双向形态切换、原生归一化、失败重试、无重复创建以及保守迁移边界。
- 原生发布：使用 `npm run ios:release` 完成干净 prebuild 和 Release 编译；固定 CMake 3.31.8 预检通过，未回退系统 CMake。`BUILD SUCCEEDED` 后覆盖安装并启动 `com.huanxue.assistantapp`。
- 真机：`huan-iphone17`，iOS 26.6.2，私人助手 Release，覆盖安装保留生产 SQLite。用户确认“顾朝希用工商银行信用卡买校服”显示为 15:00–16:00，未产生重复日程。
- 数据与兼容性：无 schema、原生依赖、权限或 Bundle ID 变化；幂等迁移只修复具备完整证据的 `time_precision`，不删除系统日程。
- 回滚：优先关闭“我的”中的苹果日历同步，再 revert PR #37；迁移写入的字段可把对应待办重新设为全天恢复，回滚不主动删除既有日程。
