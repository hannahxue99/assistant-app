# 创建时间与内容更新时间

## 背景与结论

旧实现只有 `created_at`，用户修改标题或正文后，所有页面仍显示和排序为最初创建时间。现在保留不可变的创建时间，并新增 `updated_at` 表示用户最后一次真实内容修改。

## 规则

- 新建：`created_at` 与 `updated_at` 相同。
- 用户修改标题或正文：更新 `updated_at`。
- 无改动点击完成：不写数据库，不更新时间。
- LLM 后台理解、待办完成状态、主题重命名和主题置顶：不更新时间。
- 聚合与原声列表按 `updated_at` 倒序；置顶主题仍整体优先，置顶区内部也按主题最新 `updatedAt` 倒序。
- 待办列表继续按 `due_at` 排序。

## 迁移经验

SQLite 旧表不能依赖重复执行 `ALTER TABLE`。启动时先通过 `PRAGMA table_info(entries)` 判断字段是否存在，再添加字段、用 `created_at` 回填空值并创建索引。这样新安装和已有真机数据使用同一路径，且迁移可重复执行。

## 验证

1. 打开一条旧记录，确认详情只显示创建时间。
2. 不改内容直接点完成，确认列表位置和时间不变。
3. 修改标题或正文，确认详情出现编辑时间，原声卡与聚合卡同步更新时间并重新排序。
4. 置顶多个主题，确认置顶组始终在前，组内按内容更新时间排序。
5. 完成待办或修改主题名，确认内容更新时间不变。

## 回滚

代码可回滚到本 PR 之前；数据库保留的 `updated_at` 列不会影响旧代码。SQLite 不需要删除该列。
