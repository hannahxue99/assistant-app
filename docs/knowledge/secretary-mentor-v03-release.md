# V1 当前实现基线（原“秘书 + 导师”V0.3 发布基线）

> 版本说明（2026-09-17）：原 V0.3 完整愿景已升级命名为 V1。本文记录的是 2026-09-17 已交付到手机的主要基础能力，**不代表 V1 完整闭环已经完成**；完整范围和进度矩阵以 [`PRD.md`](../../PRD.md) 为准。

## 产品结论

当前实现已经把产品收敛为“一个长期懂你的私人 AI：像秘书一样帮你料理当下，像导师一样帮你看清方向”。用户只面对三个入口：

- 首页：本周待办、本周以后待办和持续事件；V1 目标中的教练提醒尚未实现。
- 小知：连续对话的统一输入入口；用户无需先选择记录、待办或困惑。
- 我的：只展示已经生效的长期记忆和设置，不展示短期上下文。

长期待办仍保存在数据层，但不再作为独立首页模块。普通对话消息完整保留；系统在后台按轮次检索和压缩，不把内部会话摘要暴露给用户。

## 数据边界与更新规则

- 对话消息：保存原话、角色、时间和处理状态，是可回看的交流记录，不直接等同于记忆。
- 待办：明确、可执行的行动对象；本周待办与更远期待办分区展示，避免重复。
- 事件：长期主线的当前快照加增量历史。标题保持稳定；新输入追加进展，并更新当前状态、关键进展和关联待办，不覆盖历史原话。
- 长期记忆：只保留稳定且未来仍有帮助的用户事实、偏好、目标、约束和重要关系。用户明确表达或多次重复的内容可生效；推断内容先等待确认。
- 短期状态：服务当前对话和近期判断，可自动使用并撤销，但不出现在“我的”。

同一轮对话可以同时更新事件和生成待办。是否属于一次性行动、是否需要待办、关联哪条事件以及日期语义都由模型判断；代码只校验协议、对象权限、日期合法性和事务结果，不用关键词规则替代语义判断。

## 模型与本地代码的职责

1. 本地检索与当前输入相关的消息、事件、待办和记忆，并给模型提供有界上下文。
2. 模型返回自然回复和结构化操作候选，包括事件增量、待办、记忆和删除意图。
3. 本地协议层校验结构、对象 ID、日期和业务约束，再在 SQLite 事务中落库。
4. UI 展示操作回执，并允许撤销本轮实际变更；失败时整轮不显示为成功。
5. 决策日志记录候选、拒绝原因和提交结果，不记录密钥或完整系统提示词。

模型负责“理解用户想做什么”，代码负责“只让合法、可审计、可撤销的变更真正发生”。删除事件时，模型应先确认是否连关联待办一起删除；当前实现仍主要依赖提示词和模型遵守该流程，本地尚未把“用户已明确选择删除策略”做成强制状态机，这是发布后的首要防护改进。

## 交互与导航基线

- 小知采用单一输入框和统一回复样式，回复通过 SSE 流式出现。
- 处理中输入框仍可编辑下一段草稿；右侧按钮变为停止，点击只中止当前请求，不提交草稿，也不执行未完成的业务操作。
- 待办回执跳转到对应待办分区：本周事项进入“本周待办”，更远期事项进入“全部待办”；事件回执进入事件详情。
- 从小知或事件详情返回时恢复原页面和滚动位置，不强制跳到底部或首页待办区。
- 操作回执保持紧凑，显示实际生成、更新、删除或撤销的对象。
- 删除待办时同步删除事件中的关联；删除事件时可选择保留或一并删除关联待办，两种结果都支持整轮撤销。

## 易错点与可复用经验

- PR #18 和 #19 都基于 PR #17，不能直接把三个 PR 随意 squash 到 `main`；按 #17 → #18 → #19 合并并在每次基线变化后重新检查 CI。
- 流式文字只是预览，业务操作必须等完整结构化响应通过校验后再提交。
- 模型输出格式失败时重新请求完整推理；不要让第二次模型调用只“修 JSON”。
- 事件关闭后从活跃列表隐藏，但数据和增量历史保留；撤销恢复原状态。
- Tunnel URL 属于临时开发端点，不能视为发布地址；Release 不依赖 Metro。
- 新增操作协议时要同步更新提示词、协议解析、校验、数据库事务、回执、撤销和聚合测试。
