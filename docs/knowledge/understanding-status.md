# 理解状态反馈

## 产品决策

- 原文先保存，LLM 后台理解；任何异常都不能阻塞记录。
- LLM 处理中只做行内轻提示，不弹窗。
- 单条失败显示“原文已保存，暂未整理”，允许原地重试。
- 最近 10 分钟至少 3 条失败时，升级为页面级提示并引导检查设置。
- LLM 成功后记录自然进入聚合主题，不展示多余的“成功”状态。
- 用户关闭理解引擎或未配置 Key 时，C 端不展示“仅本地规则”。

## 状态映射

- `pending`：LLM 正在处理。
- `ok + llm`：理解成功。
- `failed`：LLM 或协议校验失败，规则结果已保存。
- `ok + rule`：纯规则结果，不在 C 端显示状态。

## 工程经验

- “记录已保存”和“理解已成功”是两个独立事实，界面必须分别表达。
- 请求必须有超时，否则处理中状态可能永久存在。
- 重试只更新原记录，禁止再次插入，避免重复原声、待办和通知。
- 批量异常提示应基于时间窗口，避免历史失败永久污染当前页面。

## 验收

- 自动验证：状态阈值纯函数测试、类型检查和既有回归测试。
- 真机验证：处理中、失败、重试成功、3 条失败升级、纯规则无提示。
